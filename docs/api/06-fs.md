# Domain: fs (explorer) / dl / share_link / upload / backup config

## `fs/ls/`
- resttree proxy. `reader root:"result.entries"`. Entries =
  `Fbx.os.app.explorer.ExplorerModel`: `mimetype:string`, `name:string`,
  `type:string` ("dir"/"file"), `modification:date`, `size:int`,
  `path:string`, `decoded_path:string`, `filecount:int`, `foldercount:int`,
  `link:bool`, `hidden:bool`, `leaf:bool`, `text:string`, `iconCls:string`.
  The tree proxy composes the path into the URL (`escapePath`,
  URL collapses `//`).

## File operations — all `POST` with `jsonData`, return `{result:{id:<task id>}}`
tracked on `fs/tasks/` (call sites: `Fbx.os.app.explorer.FsTask`):

- `fs/cp/` — `{files:[<path>…], dst:<dir>, mode:"overwrite"|"both"|"recent"}`
- `fs/mv/` — same body as cp (conflict menu: move-overwrite/keepboth/keeprecent)
- `fs/rm/` — `{files:[<path>…]}`
- `fs/extract/` — `{src:<path>, dst:<dir>, password:<string|null>,
  delete_archive:bool, overwrite:bool}`
- `fs/archive/` — `{files:[<path>…], dst:<archive path>}`
- `fs/repair/` — `{src:<path>, delete_archive:bool}` (par2 repair)
- `fs/mkdir/` — `{parent:<dir>, dirname:<name>}`
- `fs/mkpath/` — `{path:<full path>}` (returns `created_path`)
- `fs/rename/` — `{src:<path>, dst:<new name>}`

## `fs/tasks/`
- rest proxy. `result` entries = `Fbx.os.app.explorer.FsTaskModel`
  (fields not fully captured) with at least `state` ("running"/"paused"),
  `error` (string code, mapped via `FsTaskModel.taskErrorStr`),
  progress/title shown in the task column widget. Record `save()` (PUT) with
  `state` pauses/resumes a task.

## `dl/` — file download from the box
- `GET dl/<url-encoded path>?inline=1` (browser plays inline),
  `?inline=0` (download), `?inline=1&thumbnail=480p` (image preview).

## `share_link/`
- rest proxy. `result` = `Fbx.os.app.explorer.ShareLinkModel`: `token:string`,
  `path:string`, `decoded_path:string`, `expire:int`, `expiredate:date`,
  `internal:bool`, `fullurl:string`, `mailto:string` (mailto/fullurl are
  client-composed `[inferred]`).

## `backup/config/export` and `backup/config/import`
- Config backup export (GET download) / import (POST upload)
  `[inferred from names + settings screen]`.

## Uploads
- **WebSocket `…/upload`** (preferred; `Fbx.os.app.explorer.FsUpload`):
  - client → server JSON: `{"action":"upload_start","request_id":3615,
    "size":<int>,"dirname":<dest dir>,"filename":<name>,
    "force":"overwrite"|"resume"|null}` then raw binary chunks
    (CHUNK_SIZE = 512*1024, back-pressure via `bufferedAmount` vs
    MAX_BUFFER_SIZE = 32*1024*1024), then
    `{"action":"upload_finalize","request_id":3615}`.
  - server → client JSON: `{action:"upload_start"|"upload_data"|
    "upload_finalize"|"upload_cancel", success:bool, …}`; on
    `upload_start` failure with `error_code:"destination_conflict"` the
    reply carries `file_size:<int>` and the client may retry with
    `force:"overwrite"` or `force:"resume"` (offset = `file_size`).
  - client cancel: `{"action":"upload_cancel","request_id":3617}` then
    close(1000).
  - Directories are created first via `fs/mkpath/`; sub-dir queues.
- **HTTP multipart fallback** (`FbxConf.uploadBaseUrl` = `upload/` `[inferred]`):
  1. `POST upload/` — multipart fields: `file`, `dirname`,
     `MAX_FILE_SIZE` (4194304000), `csrf_token` (from `FbxConf.csrfToken`).
     → `result.id` = upload id.
  2. `POST upload/<id>/send` — repeat multipart sends.
- Upload monitor store: rest proxy on `upload/` —
  `Fbx.os.app.explorer.FsUploadModel`: `id:int`, `upload_name:string`,
  `dirname:string`, `size:int`, `uploaded:int`, `start_date:int`,
  `status:string`, `status_str:string`, `progress:float`, `speed:float`,
  `timeLeft:float` (client-computed).
